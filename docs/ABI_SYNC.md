# Sync contract ABIs

Use `abi:sync` when a required ABI/interface is missing or stale, or the intended contract implementation has changed. Confirm the intended deployment and version before choosing the source; historical votes may need an earlier implementation ABI. The task generates files for one contract name per run:

- `abi/<Name>.abi.ts`: the full input ABI, exported as `<Name>_ABI` with `as const`.
- `contracts/interfaces/I<Name>.sol`: a Solidity `0.8.26` interface for state-changing calls.

Both paths are relative to the Hardhat project root. Existing files are overwritten without a prompt, so inspect their diff after generation. The name controls the filenames and exports; use PascalCase with letters and digits, starting with an uppercase letter (for example, `StakingRouter`).

Maintain files marked `Generated by npm run abi:sync` by rerunning the command with the intended source and options. Inspect any existing hand-maintained interface before replacing it: it may include views or custom declarations that this generator omits. Use `--skip-sol` when only the TypeScript ABI needs updating.

## Prerequisites

Use the repository's Node version (`nvm use`) and installed npm dependencies. Solidity generation also needs Foundry's `forge` on `PATH`; use v1.8.1 as specified in the [README](../README.md#install). TypeScript-only generation with `--skip-sol` does not need Forge.

| Input mode                    | Required environment                                                                        |
| ----------------------------- | ------------------------------------------------------------------------------------------- |
| Etherscan, default behavior   | `ETHERSCAN_TOKEN` and `ETH_MAINNET_RPC_URL` or `ETH_HOODI_RPC_URL` for the selected network |
| Etherscan with `--proxy-abi`  | `ETHERSCAN_TOKEN`; no RPC needed                                                            |
| Local JSON with `--from-file` | No Etherscan token or RPC needed                                                            |

The Hardhat config loads `.env`. For a local-only run without loading it, prefix the command with `DOTENV_CONFIG_PATH=/dev/null`. A missing-token warning from config loading is harmless for local input and `--help`.

## Choose the source

Run the examples from the repository root. The task supports `mainnet` (default) and `hoodi`; select the source chain with `--network-name`.

### Address registry

```bash
npm run abi:sync -- StakingRouter
npm run abi:sync -- Voting --network-name hoodi
```

Without `--address` or `--from-file`, the task converts the name to a Solidity constant (`StakingRouter` → `STAKING_ROUTER`) and looks it up in [MainnetAddresses.sol](../contracts/addresses/MainnetAddresses.sol) or [HoodiAddresses.sol](../contracts/addresses/HoodiAddresses.sol). A missing constant fails with a hint to provide an address.

### Explicit deployed address

```bash
npm run abi:sync -- StakingRouter --address 0xFdDf38947aFB03C621C71b06C9C70bce73f12999 --network-name mainnet
```

`--address` overrides registry lookup. Use it for contracts outside the registry or a specific deployment; it does not update the address libraries. The address and every followed implementation must have a verified ABI on Etherscan.

### Local ABI or compiler artifact

```bash
DOTENV_CONFIG_PATH=/dev/null npm run abi:sync -- MyContract --from-file ./MyContract.json
DOTENV_CONFIG_PATH=/dev/null npm run abi:sync -- MyContract --from-file ./MyContract.json --skip-sol
```

Replace `./MyContract.json` with a local file containing either a JSON ABI array or a compiler artifact with an `abi` array. For example, a minimal ABI array is:

```json
[
  {
    "type": "function",
    "name": "setManager",
    "stateMutability": "nonpayable",
    "inputs": [{ "name": "manager", "type": "address" }],
    "outputs": []
  }
]
```

An artifact can wrap that array as `{ "abi": [...] }`. A TypeScript `.abi.ts` module is not JSON input. Local input takes precedence over Etherscan and registry resolution. The consumed ABI fields are structurally validated before any output is written; this does not establish that the ABI matches the intended deployment or version.

Relative `--from-file` paths resolve from the process working directory, while output paths and registry paths resolve from the Hardhat project root. npm scripts normally run from the package root; when invoking Hardhat directly from a subdirectory, use an absolute input path or account for that directory. `--network-name` is still validated for local input.

## Select Solidity methods

```bash
DOTENV_CONFIG_PATH=/dev/null npm run abi:sync -- MyContract --from-file ./MyContract.json --methods setManager
```

By default, Solidity includes every function whose `stateMutability` is `nonpayable` or `payable`. It omits view/pure functions, events, errors, constructors, fallback and receive entries. The TypeScript ABI retains all input entries and metadata.

`--methods name1,name2` narrows only the Solidity functions, preserving ABI order. It matches exact names and includes every state-changing overload of each name; signatures such as `setManager(address)` are not selectors for this option. Unknown names and view/pure-only names fail: check the requested names and source ABI version against the available methods listed in the error. `--skip-sol` skips method selection entirely and leaves any existing Solidity interface untouched.

Tuples in selected functions become structs and need `internalType` struct names and named fields; conflicting definitions with the same struct name fail. Enums retain their ABI integer type. Legacy ABI entries without `stateMutability` remain in TypeScript but are omitted from Solidity, even if they have legacy `constant`/`payable` fields.

TypeScript is formatted with the repository's Prettier configuration; Solidity is formatted with `forge fmt` before either output is written. Generation formats interfaces but does not compile them.

## Proxy resolution

The default Etherscan mode checks on-chain storage even for a contract that does not look like a proxy. It reads the EIP-1967 implementation slot, then the beacon slot and the beacon's `implementation()` getter. For a proxy-looking contract it also tries a legacy `implementation()` getter when the slots are empty. Etherscan metadata, a proxy-like contract name, an ABI without functions, or recognized proxy methods trigger that legacy fallback.

These reads use `latest`; Etherscan's implementation address is not the source of truth after an upgrade. RPC failures, loops, unresolved proxy-looking contracts and an unverified implementation fail. A chain can finish successfully with at most two implementation hops.

Use `--proxy-abi` when you need the supplied address's own ABI, such as proxy upgrade methods:

```bash
npm run abi:sync -- StakingRouterProxy --address 0xFdDf38947aFB03C621C71b06C9C70bce73f12999 --proxy-abi
```

This skips all implementation resolution and returns only the proxy's own ABI; it is not a substitute for the implementation ABI and does not merge the two.

## Troubleshooting

Each Etherscan contract-info request retries rate limits and transient failures up to six total attempts, with waits of 0.5, 1, 2, 4 and 8 seconds. This retry policy applies per Etherscan request, not to RPC calls or the whole CLI run. If those failures persist, retry the same command later; rejected API keys and unverified contracts need the actions below.

| Error                                                                    | Action                                                                                                                                                                  |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Etherscan rejects the API key                                            | Check the configured `ETHERSCAN_TOKEN`.                                                                                                                                 |
| No RPC for the selected network                                          | Check the RPC variable listed under prerequisites and that its endpoint is available and serves the selected chain.                                                     |
| Contract/implementation not verified, or proxy implementation unresolved | Use `--from-file` only with an ABI whose origin and intended contract/implementation version you have established; retain that source information for review.           |
| Local file unreadable or invalid ABI JSON                                | Check the input path and reported cause; use valid JSON containing an ABI array or artifact. Resolve malformed fields against the correct source artifact.              |
| `forge fmt` fails                                                        | Check Forge is installed on `PATH` and inspect the reported error against the tuple/type requirements above. Formatting failure occurs before either output is written. |

## Flag reference

| Argument                        | Effect / default                                                     |
| ------------------------------- | -------------------------------------------------------------------- |
| `<Name>`                        | Required output name; also selects the registry constant when needed |
| `--network-name mainnet\|hoodi` | Source network; default `mainnet`                                    |
| `--address 0x...`               | Explicit address instead of registry lookup                          |
| `--from-file path.json`         | Local ABI array or artifact instead of Etherscan                     |
| `--methods name1,name2`         | Solidity method names; default all state-changing functions          |
| `--skip-sol`                    | Write only the full TypeScript ABI                                   |
| `--proxy-abi`                   | Use the supplied address's own Etherscan ABI                         |

For the current CLI syntax, run `npm run abi:sync -- --help`.

## Review and rerun

1. Check the generated `Source` header against the intended file or network/address and implementation chain. Review added/removed functions, signatures, events, errors and mutability against the consumers that encode calls or read state.
2. Preserve the exact command, name, network/address or input file, method list and flags. For local input, retain the JSON and its origin/version. Headers record source information but do not record all options. Etherscan runs read current state and can change after upgrades; the task has no block-pinning, manifest or batch mode.
3. Check the generated paths with Prettier and Forge, then run the repository checks and affected omnibus tests. For the `MyContract` example:

```bash
npx prettier --check abi/MyContract.abi.ts
forge fmt --check contracts/interfaces/IMyContract.sol
npx tsc --noEmit
npm run lint
npm test
```

Skip the Forge check for a TypeScript-only run. When a Solidity omnibus consumes the interface, also compile it with `npm run omnibus:build -- <omnibus_name>` and run its tests with `npm run omnibus:test -- <omnibus_name>` against the intended fork.
